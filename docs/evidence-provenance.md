# Evidence provenance and comparison contract

The evidence pack is generated by `mlflow_ai_assurance_lab evidence` from measured offline
evaluation results. It is not a signature, an independent timestamp, a compliance record, or proof
that the small synthetic evaluation represents production behavior.

## Versioned artifacts

| Artifact | Schema | Purpose |
|---|---|---|
| `manifest.json` | `2.0` | Overall evidence version, provenance, MLflow anchors, artifact checksums, and comparison profile. |
| `summary.json` | `2.0` | Input bindings, aggregate metrics, decisions, and variant-level MLflow identifiers. |
| `case-results.json` | `2.0` | Complete per-case actions, citations, scores, and trace anchors. |
| `control-status.json` | `2.0` | Derived risk/control/test/evidence/decision rows from measured results and the control catalog. |

Unknown schema or evidence versions, missing or extra fields, wrong types, invalid digests,
inconsistent relations, stale current-input bindings, unsafe configured content, or altered files
fail validation. The validator independently reloads current versioned inputs, recomputes gate and
control status, checks complete case-to-trace coverage, renders the expected report, and recomputes
the material comparison digest. A changed manifest checksum cannot override those checks.

## Provenance fields

The manifest records the installed application and MLflow versions, Python version, an application
source digest over the package and reproducibility files, the Git commit plus `clean`, `dirty`, or
`unavailable` working-tree marker, version and SHA-256 for dataset/corpus/policy/control catalog,
the exact policy thresholds, MLflow experiment/run IDs, and SHA-256 for each generated artifact.
Only repository-relative logical identities are stored; local tracking URIs and personal or
absolute paths are excluded.

The Git marker describes generation context. The source digest is the machine-independent binding
to the executable lab content. A `dirty` marker does not make a result pass or fail, but it requires
review because the commit alone cannot reconstruct the generating tree.

## Material and volatile comparison

The comparison profile `material-assurance-v1` classifies fields as follows:

- Deterministic/material: input and source digests, versions, thresholds, tool versions, metrics,
  decisions, failed metrics, per-case behavior, and derived control status.
- Normalizable context: Git commit and working-tree marker. These identify context but do not by
  themselves represent a semantic result change when source/input digests are unchanged.
- Volatile: normalized UTC timestamp, MLflow experiment/run/trace IDs, and their report rendering.

The manifest's `material_digest` hashes the validated pack after removing only the documented
normalizable and volatile fields. Compare two packs with:

```bash
uv run python -m mlflow_ai_assurance_lab compare-evidence LEFT_DIR RIGHT_DIR
```

Exit `0` means material content matches; the JSON result distinguishes byte-identical packs from
`volatile_or_normalizable_only`. Exit `1` means `material_drift`. Invalid, stale, incomplete, or
unsafe inputs fail instead of producing a comparison success.

## Residual limits

The pack is local and hash-linked but not cryptographically signed, independently timestamped, or
stored in append-only infrastructure. Hashes detect changes relative to trusted current inputs;
they do not establish author identity or custody. MLflow identifiers are local review anchors and
are intentionally excluded from semantic drift. Independent release review remains outside this
Phase 2 governance increment and is planned for Phase 3.
